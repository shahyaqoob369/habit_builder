# Architecture

_Set up in step 2 (2026-10-18). Update this file whenever the structure changes._

## Stack

| Concern | Choice | Why |
|---|---|---|
| State management | **flutter_riverpod 3** | Compile-safe dependency injection, testable, scales from UI state to repositories |
| Navigation | **go_router 17** (`MaterialApp.router`) | Declarative routes, deep links, redirects for auth and onboarding |
| Lints | **very_good_analysis 10** (strict) | Catches bugs and keeps style consistent. `public_member_api_docs` is off because this is an app. |
| Text and translation | **gen-l10n** (`lib/l10n/arb/app_en.arb`) | All user-facing text in one place, ready for more languages |
| Theme | Tokens in `lib/app/theme/` + `ThemeExtension` for colors | One source of truth from Figma; dark mode is possible later |
| Backend (from step 13) | Firebase + RevenueCat (default, see BACKEND_SPEC) | |

## Folder layout

```
lib/
├── main.dart                     bootstrap: bindings, portrait lock, edge-to-edge, ProviderScope
├── app/
│   ├── app.dart                  MaterialApp.router: theme, localization, status bar style
│   ├── router/app_router.dart    AppRoute enum + appRouterProvider (GoRouter)
│   └── theme/
│       ├── app_palette.dart      raw Figma colors (never used by widgets directly)
│       ├── app_colors.dart       semantic colors: ThemeExtension, read with context.colors
│       ├── app_text_styles.dart  AppFonts + AppTextStyles (Fredoka display, Manrope text)
│       ├── app_dimens.dart       AppSpacing, AppRadii, AppShadows
│       └── app_theme.dart        ThemeData built from the tokens
├── core/
│   ├── extensions/               BuildContext helpers (context.colors)
│   └── widgets/                  shared UI components (from step 3)
├── features/
│   └── <feature>/
│       ├── presentation/         pages and widgets (+ Riverpod controllers)
│       ├── application/          use-case logic / services (when needed)
│       ├── domain/               models (when needed)
│       └── data/                 repositories and data sources (when needed)
└── l10n/
    ├── arb/app_en.arb            source strings
    ├── gen/                      generated by `flutter pub get` (gitignored)
    └── l10n.dart                 export + context.l10n

test/                             mirrors lib/; helpers/pump_app.dart wraps widgets in theme, l10n and ProviderScope
```

Planned features: `onboarding`, `auth`, `shell`, `home`, `habits`, `courses`, `community`, `profile`, `settings`, `premium`. `design_system` is a developer preview page.

## Rules of thumb

1. **Widgets never hardcode design values.** Colors come from `context.colors`, text from `AppTextStyles`, and spacing, radii and shadows from `AppSpacing` / `AppRadii` / `AppShadows`. Add a missing token before using it.
2. **User-facing text lives in the ARB file** and is read with `context.l10n.key`. Display headings are uppercased in code.
3. **Layouts adapt to the width.** Figma frames are 414 dp wide; the test phone (Realme C3) is 360 dp. Keep the design's padding, sizes and type; let widths flex (Expanded, padding), and avoid fixed full-width sizes and absolute positions.
4. **Shared components go in `core/widgets/`** once two screens need them. Screen-specific widgets stay in their feature folder.
5. **Screens don't talk to storage.** Pages watch Riverpod providers, providers call repositories, and repositories call data sources. Until the backend steps, repositories return sample data.
6. **Tests mirror `lib/`.** Every component and page gets widget tests for its key behavior; pure logic gets unit tests.
